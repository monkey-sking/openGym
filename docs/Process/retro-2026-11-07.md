# 复盘回填：视频同步计时联动、设置页去冗余小字与手表端动态倒计时体验优化

> 每修完一个用户报的问题必须填。门禁「复盘回填」检查项会比对本文与源码改动的先后。
> 四选一：防止（做不出这个错误）/ 拦截（做出来但被机器挡住）/ 暴露（漏到用户但被看见）/ 没挡住。
> 答「没挡住」必须新增一条机制——否则下次还会发生。

- **日期**: 2026-11-07
- **用户看到的现象**:
  1. 手机与电脑扩展进行视频同步时，计时或跟练动作在手机尚未点击开始计时（Work）时，电脑端视频便已提前自动播放。
  2. 手机视频同步设置页与 Chrome 扩展弹窗中存在较多次级标签、解释性小字和冗余提示（如重复解释配对步骤和状态说明）。
  3. 手表端训练进行与组间休息时，倒计时数字字号固定，最后 5 秒缺少视觉冲击力，且下一组器械预备提示不明显。
- **真实根因**:
  1. `frontend/src/lib/video-sync.js:198-206` 中 `shouldAutoplay` 未区分重量动作与计时/跟练动作，只要 `active` 存在且非暂停态就默认触发 `play: true`；同时缺少对 `useUI.work` 状态订阅的实时事件同步。
  2. `frontend/src/views/VideoSyncSettings.jsx:470-520` 保留了多处 Section footer 和 subtitle 说明文字，未完全贯彻“让布局本身承担解释”的界面规范。
  3. `frontend/ios/App/Watch/OpenGymWatchApp.swift:1120-1280` 手表倒计时缺乏三阶段（前3秒确认动作、平稳期保持克制、末尾5秒动态放大脉冲）焦点切换。
- **为什么之前没发现**:
  1. 原 `video-sync.test.js` 只测试了普通动作的启动与暂停，未覆盖计时动作下 `work` 状态切换的生命周期。
  2. 界面评审此前聚焦在功能跑通，未严格按照“避免不必要的次级标签与说明文字”进行视觉精简。
- **被哪一层挡住**: 没挡住（真机联调与交互体验验收暴露）。
- **新增机制**:
  1. `video-sync.js` 接入 `onUIChange` 订阅 `useUI.work` 变更，并在 `video-sync.test.js` 增加针对计时/跟练动作与自动播放判断的完整自动化测试（74行新增用例全部 PASS）。
  2. 精简 `VideoSyncSettings.jsx` 及 Chrome 扩展弹窗中的辅助说明，仅保留必要交互控件与纯净状态指示。
  3. Watch 端落地 `DynamicExerciseTimer` 与 `NextGearCue`，提升高强度训练时的即时可读性。
- **同类还有几处**:
  - 全局审查 `frontend/src/views/VideoSyncSettings.jsx`、`tools/video-sync-extension/popup.html` 与 `popup.js`，全部次级文案与重复提示已收敛完毕。
