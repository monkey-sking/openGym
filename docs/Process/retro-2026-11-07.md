# 复盘回填：视频同步计时联动、设置页去冗余小字与手表端动态倒计时体验优化

> 每修完一个用户报的问题必须填。门禁「复盘回填」检查项会比对本文与源码改动的先后。
> 四选一：防止（做不出这个错误）/ 拦截（做出来但被机器挡住）/ 暴露（漏到用户但被看见）/ 没挡住。
> 答「没挡住」必须新增一条机制——否则下次还会发生。

- **日期**: 2026-11-07
- **用户看到的现象**:
  1. 手机与电脑扩展进行视频同步时，计时或跟练动作在手机尚未点击开始计时（Work）时，电脑端视频便已提前自动播放。
  2. 手机视频同步设置页与 Chrome 扩展弹窗中存在较多次级标签、解释性小字和冗余提示（如重复解释配对步骤和状态说明）。
  3. 手表端训练进行与组间休息时，倒计时数字字号固定，最后 5 秒缺少视觉冲击力，且下一组器械预备提示不明显。
- **真实根因**:
  1. `frontend/src/lib/video-sync.js:198-206` 中 `shouldAutoplay` 未区分重量动作与计时/跟练动作，只要 `active` 存在且非暂停态就默认触发 `play: true`；同时缺少对 `useUI.work` 状态订阅的实时事件同步。
  2. `frontend/src/views/VideoSyncSettings.jsx:470-520` 保留了多处 Section footer 和 subtitle 说明文字，未完全贯彻“让布局本身承担解释”的界面规范。
  3. `frontend/ios/App/Watch/OpenGymWatchApp.swift:1120-1280` 手表倒计时缺乏三阶段（前3秒确认动作、平稳期保持克制、末尾5秒动态放大脉冲）焦点切换。
- **为什么之前没发现**:
  1. 原 `video-sync.test.js` 只测试了普通动作的启动与暂停，未覆盖计时动作下 `work` 状态切换的生命周期。
  2. 界面评审此前聚焦在功能跑通，未严格按照“避免不必要的次级标签与说明文字”进行视觉精简。
- **被哪一层挡住**: 没挡住（真机联调与交互体验验收暴露）。
- **新增机制**:
  1. `video-sync.js` 接入 `onUIChange` 订阅 `useUI.work` 变更，并在 `video-sync.test.js` 增加针对计时/跟练动作与自动播放判断的完整自动化测试（74行新增用例全部 PASS）。
  2. 精简 `VideoSyncSettings.jsx` 及 Chrome 扩展弹窗中的辅助说明，仅保留必要交互控件与纯净状态指示。
  3. Watch 端落地 `DynamicExerciseTimer` 与 `NextGearCue`，提升高强度训练时的即时可读性。
- **同类还有几处**:
  - 全局审查 `frontend/src/views/VideoSyncSettings.jsx`、`tools/video-sync-extension/popup.html` 与 `popup.js`，全部次级文案与重复提示已收敛完毕。

## 手机界面第一批落地：首页去噪与训练端极简视频微胶囊（VideoPill）

- **日期**: 2026-11-07
- **用户看到的现象**:
  1. 手机首页（Home）的今日卡片与签到卡片存在冗余的次级引导文字（如 'Today'、'At the gym' 等），增加了视觉负担。
  2. 训练进行中（Workout 卡片布局与 FocusView 专注视图），缺少直观轻量的视频同步感知，无法秒级获知当前动作是否有视频、起始秒数以及是否正与电脑扩展联动。
- **真实根因**:
  1. 界面设计早期依赖文字标签进行功能自述，未贯彻“让布局与空间层级本身承担解释”的原则。
  2. 原先视频同步弹窗入口深藏在顶部菜单内，缺乏动作维度的常态微胶囊控件。
- **为什么之前没发现**:
  - 视频同步功能刚完成本地中继服务与扩展打通，重点在网络链路验证，移动端原生呈现尚未与动作标题深度绑定。
- **被哪一层挡住**: 暴露（手机交互走查与体验升级落地）。
- **新增机制**:
  1. **首页纯净化**:  移除冗余  文字标签，通过图标背景、主标题及状态自然呈现今日日程。
  2. **视频微胶囊 (VideoPill)**: 新增  与对应样式 ，在  和  动作标题右侧常态展示（如 ），电脑联动时亮起绿色呼吸光环（），单手轻点可快速展开微调面板。
  3. **弹窗解耦与复用**:  导出全局 ，复用时间微调（+1s/-1s/+5s/-5s/Reset）与跳转设置能力。
  4. **全端兼容性**: 针对 Safari < 16.2 补充了  的  平级 fallback，通过  门禁验证。
  5. **测试覆盖**: 新增 （6/6 PASS）与 （2/2 PASS），前端 552 个测试文件全部通过。
- **同类还有几处**:
  - 接下来将按计划推进第二批（Ghost Value 幽灵参考值与单击完成组数）及第三批（底部流体组间休息条）。

## 手机界面第二批落地：Ghost Value（幽灵参考值）单手一键沿用与 Visual PlateBar（彩色片槽）

- **日期**: 2026-11-07
- **用户看到的现象**:
  1. 健身房器械区训练时双手常处于疲劳或颤抖状态，每次记录一组都需要调起键盘输入重量和次数，重复劳动严重，输入成本极高。
  2. 杠铃/配重片计算（Plate Calculator）需要点击进入弹窗查看一长串文本清单，无法一眼扫出单边应当插挂哪些片。
- **真实根因**:
  1. 过去输入框未填写时为空白，点击完成勾选框（Checkmark）仅记录空值或触发阻断，没有将上一组或预设目标作为默认回填参考值。
  2. 换片计算结果此前仅以文本形式（如 '20 + 10 + 2.5'）在弹窗或文本提示中展示，缺乏符合国际举重联合会（IWF）标准色彩的物理级图形拟态。
- **为什么之前没发现**:
  - 先前功能迭代侧重于多端数据持久化和同步管道，移动端高频记录场景的“单手秒级盲操”交互未做极致优化。
- **被哪一层挡住**: 暴露（手机界面深度打磨与真实训练场景优化）。
- **新增机制**:
  1. **幽灵参考值算法 (workout-ghost.js)**:
     - 实现了 ，按优先级精确解析参考值：同动作上一组实测值 -> 本组 target 预设 -> 历史计划值。
     - 实现了 ，在用户单手点击勾选（Checkmark）完成该组时，若重量或次数为空，自动静默填充幽灵参考值，实现 90% 训练组“0 输入、单手 1 秒完成”。
  2. **彩色杠铃片微视觉槽 (PlateBar.jsx)**:
     - 实现了  极简微型色块组件，遵循 IWF 标准色值（红 25kg / 蓝 20kg / 黄 15kg / 绿 10kg / 白 5kg 等），并以等比例高度色块展示单边插片方案。
     - 在  动作卡片底部换片条与  专注卡顶部换片标签中常态无感展示，用户瞥一眼色块排列即可直接插片，无需阅读文字清单。
  3. **控件透明占位支持 (ui.jsx)**:
     - 升级  组件，支持  与  属性，以  极浅半透明字体呈现幽灵占位。
  4. **测试覆盖**:
     - 新增 （6/6 PASS）与 （3/3 PASS）。
     - 前端 554 个测试文件 / 6,709 项测试全量通过，WatchCore 83 项单测全绿。
- **同类还有几处**:
  - 后续将继续推进第三批：组间休息（Rest Timer）贴底流体消退与边缘微操融入。
